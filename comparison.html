Comparison: flat-file second brain vs Wanderloots' scoped-vault approach

Last checked 2026-10-04. Neutral comparison for the series' knowledge-management arc. Not a recommendation.

Which sources this compares

  • A. "Claude Second Brain & Folder Workflow: The Complete Guide", @Bober_smart, X article, 2026-07-19. Read the article text through a public mirror; images and two code examples were not available. Post
  • B. Wanderloots, "Do I NEED A Separate Agent Vault? Hermes + Obsidian Tutorial", Patreon post, 2026-07-23. Read the public text of the post. The video it accompanies was not watched, and the post text had a truncated tail. Post

"Wanderloots' insight" was not named more precisely, so B is a best match, not a certainty. Other Wanderloots material exists and would give a different slice: "Why LLM Wiki?" (YouTube, 2026-05-04), "How To Build LLM Wiki In Obsidian?" (2026-06-04), "What Is An Agentic Librarian?" (2026-08-29), and a Patreon note on agentic memory. Ask which one was meant if the comparison should change.

What each says (claims, as stated)

A. Flat-file second brain B. Scoped vault with three access levels
Core idea A second brain is plain Markdown files in a few folders, with one root index file that tells the agent where to look One Obsidian vault with a human view and an agent view; control what the agent can see or change
Structure Folders such as notes, people, projects; root files for memory, learnings, decisions; one topic per file Three access levels: private (agent cannot see), read-only, read and write
Tools Any text editor and an agent that reads a folder; explicitly "no Obsidian, databases, or apps" Obsidian plus an agent (Hermes shown; the post says the scoping idea applies to other agents)
Who maintains it The user keeps the structure clean; the agent retrieves Agent works freely in some notes, references others without editing, never sees private ones; LLM Wiki raw files can be protected at system level (Docker, per the post)
Main worry addressed Making notes easy for an agent to navigate Not giving an agent access to every note
Memory vs knowledge Root files hold long-term memory and decisions alongside notes Separates knowledge ("a library") from agentic memory ("instructions to the librarian") as two layers of one memory stack
Index A single root index is the map Not the focus of the post text read

Evidence

  • A: no tests, benchmarks, or measurements in the text read. Claim that the agent reports a gap instead of inventing an answer is stated, not demonstrated. Author's bio: on-chain analyst. Popularity numbers come from a mirror and are not evidence of quality.
  • B: a tutorial based on the creator's own setup and a video demonstration; no independent evaluation seen. The creator is a long-running Obsidian and AI-workflow educator. The post itself says "it depends".

Tradeoffs

Where A is stronger

  • Very low setup cost; works in minutes with any editor.
  • Easy to understand and to move between tools.
  • Small collections need no extra infrastructure.

Where B is stronger

  • Addresses privacy and safety directly: what the agent can see, and what it can change.
  • Keeps raw sources safe from agent edits through enforced limits rather than trust.
  • Separates stable knowledge from the agent's working memory, which helps when notes and agent state would otherwise mix.

Where each costs more

  • A: gives an agent broad reach into whatever sits in the folders unless the user manages that separately. The text read does not discuss access limits.
  • B: more setup and more concepts to learn (access levels, vault views, system-level controls); depends on one app for the human side.

Gaps in both

  • Neither source, as read, gives measured results on answer accuracy.
  • Neither covers contradictions between notes or how stale entries are caught, beyond the user's own discipline. Karpathy's LLM Wiki note adds a "lint" step for this, which is a separate source.
  • Both rely on the user to decide what goes in.

Overlap

Both treat plain Markdown files as the base. Both put a human in charge of what the agent can use. They address different questions: A asks how to organize notes so an agent can find them; B asks how to limit what an agent may touch. They can be combined.

Generalist questions

  1. Do you need your agent to be able to see everything, or should some notes stay private?
  2. Who is checking that the notes are accurate and current?
  3. What would a wrong or invented answer cost you?
  4. How much setup are you willing to maintain?
